01 · Available now

What Lake does today.

Install it in your repo. Plans stay there. There's no Lake server, account or telemetry from the CLI, hooks, license check or Action.

Gate

Plan approval

  • The agent writes a plan; it is saved in the pull request as a versioned file.
  • A teammate or a manager reviews it, comments on exact lines, and can request changes.
  • Approval is bound to that exact version. Edit one word and it no longer applies.
  • A PR check stays red until the current plan is approved, so unapproved work can't merge.
About Gate

Meter

Cost control

  • Every step gets a complexity rating, a recommended model and a $ range.
  • A per-run cap stops and asks before the agent spends more.
  • Above a limit you set, a budget owner must also approve that exact plan version.
  • Reviewers can suggest a cheaper model, a dropped step or a tighter cap.

02 · How it works

Plan, review, then build.

The same loop for every agent run on the team. See it on the home page

  1. 1. The agent writes a plan

    When Claude Code leaves plan mode, the plan is saved to your repo. Cursor and other agents use the CLI.

  2. 2. Meter puts a cost on every step

    A recommended model and a $ range per step, so the review covers what the plan will cost, too.

  3. 3. Gate holds it for review

    A teammate or a manager approves that exact version, in the review app, on GitHub or from the agent chat.

  4. 4. The agent builds, within a cap

    Edits wait for approval. During the run, the cap stops and asks before spending more.

04 · What's next

An early prototype, beyond today's loop.

We're exploring a layer that sits on top of Linear and GitHub: tickets checked against what actually shipped, blockers with an owner and a date, and a cost on trade-offs before you commit. No integrations are live yet.

Ticket vs. reality

Will flag tickets whose status doesn't match the PRs, CI runs and deploys behind them, with the evidence linked.

Blocker loop

Every blocker will get an owner and an agreed date, with follow-ups until it's cleared.

Trade-off planner

A new request will turn into scenarios (what moves, how much delay, engineering and AI cost) before you approve it.
