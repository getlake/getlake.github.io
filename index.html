01 · Shift left

Catch the wrong approach at the plan, not the PR.

By the time a pull request is ready, the agent has spent the tokens and you've spent the hours. Changing course in a plan costs a sentence. Changing it in a diff costs a rewrite.

The right problem

A teammate reads the agent's plan and comments on exact lines, so a misread ticket is caught before any code exists.

The right plan

Reviewers push back on the approach, the order of steps or a risky migration while it's still a few lines of text.

The right cost

Every step gets a recommended model and a $ range. Swap in a cheaper model, drop a step or set a cap in one click.

02 · How it works

Plan, review, then build.

Lake runs in your repo and on GitHub. Plans stay in your repo, and there's no Lake server, account or telemetry.

  1. 1. The agent writes a plan

    When Claude Code leaves plan mode, the plan is saved to your repo as a versioned file. Cursor and other agents use the CLI.

  2. 2. Lake puts a cost on every step

    A complexity rating, a recommended model and a $ range per step, so the review covers what the plan will cost, too.

  3. 3. A teammate reviews it

    In the Lake review app, on GitHub or from your agent chat. Edit one word of the plan and the approval no longer applies.

  4. 4. The agent builds, within a cap

    Edits wait for the approval, and the PR can't merge without it. During the run, a cap stops and asks before spending more.
